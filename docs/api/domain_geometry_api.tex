\section{Domain Geometry Module API Reference}
\label{sec:domain_geometry_api}


This section provides a comprehensive reference for the \texttt{domain\_geometry.py} 
geometry module, which provides 
lean geometry management for BioNetFlux. 
The geometries that BioNetFlux considers are the union of 1-dimensional rectilinear arcs (also called {\em domains} within the code) embedded in a 2 dimensional plane.  The individual domains are represented using the class {\tt DomainInfo}, while the whole geometry is represented using the class {\tt DomainGeometry}, that stores a list {\tt domains} of {\tt DomainInfo} object and a list {\tt connections} of {\tt ConnectionInfo} objects

\begin{notebox}
	In BioNetFlux, we use the word {\bf connection} to indicate a geometrical connection between two arcs, and the word {\bf constraint} to indicate the physical relation imposed in a connection point between unknowns defined on the two arcs.
\end{notebox}


\subsection{Module Overview}

The module contains three main classes and several constants:
\begin{itemize}
    \item \texttt{DomainInfo}: Data container for individual domain properties
    \item \texttt{ConnectionInfo}: Data container for connectivity and boundary conditions
    \item \texttt{DomainGeometry}: Main geometry manager for collections of domains
\end{itemize}




\subsection{DomainInfo Class}
\label{subsec:domaininfo_class}

A dataclass container for domain geometric information, relative to individual segments in the network geometry.

\subsubsection{Attributes}

\begin{longtable}{|p{3cm}|p{3.5cm}|p{6cm}|}
\hline
\textbf{Attribute} & \textbf{Type} & \textbf{Description} \\
\hline
\endhead

\texttt{domain\_id} & \texttt{int} & Unique identifier for the domain within the geometry \\
\hline

\texttt{extrema\_start} & \texttt{Tuple[float, float]} & Physical coordinates ($x_1$, $y_1$) of domain start point \\
\hline

\texttt{extrema\_end} & \texttt{Tuple[float, float]} & Physical coordinates ($x_2$, $y_2$) of domain end point \\
\hline

\texttt{domain\_start} & \texttt{float} & Parameter space start coordinate (default: 0.0) \\
\hline

\texttt{domain\_length} & \texttt{float} & Parameter space length (default: Euclidean distance) \\
\hline

\texttt{name} & \texttt{Optional[str]} & Human-readable name for the arc \\
\hline

\texttt{display\_color} & \texttt{str} & Color for matplotlib plotting (default: ``blue") \\
\hline

\texttt{metadata} & \texttt{Dict[str, Any]} & Additional domain-specific data storage \\
\hline

\end{longtable}

\subsubsection{Methods}

\paragraph{Constructor}
\begin{lstlisting}[language=Python, caption=DomainInfo Constructor]
def __init__(self, domain_id: int, 
             extrema_start: Tuple[float, float],
             extrema_end: Tuple[float, float],
             domain_start: float = 0.0,
             domain_length: float = 1.0,
             name: Optional[str] = None,
             display_color: str = "blue",
             metadata: Dict[str, Any] = None)
                          
def __post_init__(self)
# Computes domain_lenght from extrema, if not provided
\end{lstlisting}

\textbf{Parameters:}
\begin{itemize}
    \item \texttt{domain\_id}: Unique domain identifier
    \item \texttt{extrema\_start}: Start point ($x_1$, $y_1$) in physical coordinates
    \item \texttt{extrema\_end}: End point ($x_2$, $y_2$) in physical coordinates
    \item \texttt{domain\_start}: Parameter space origin (optional, default: 0.0)
    \item \texttt{domain\_length}: Parameter space length (optional, default: calculated)
    \item \texttt{name}: Domain name (optional)
    \item \texttt{display\_color}: Color for matplotlib plotting (optional, default: "blue")
    \item \texttt{metadata}: Additional properties (optional)
\end{itemize}

\textbf{Usage Example:}
\begin{lstlisting}[language=Python, caption=DomainInfo Usage]
# Create a domain from (0,0) to (1,1)
domain = DomainInfo(
    domain_id=0,
    extrema_start=(0.0, 0.0),
    extrema_end=(1.0, 1.0),
    name="diagonal_segment"
)
# domain_length will be automatically set to sqrt(2)
\end{lstlisting}

\paragraph{euclidean\_length()}\leavevmode
\begin{lstlisting}[language=Python, caption=Euclidean Length Calculation]
def euclidean_length(self) -> float
\end{lstlisting}

\textbf{Returns:} \texttt{float} - Euclidean distance between \texttt{extrema\_start} and \texttt{extrema\_end}

\textbf{Formula:} $\sqrt{(x_2-x_1)^2 + (y_2-y_1)^2}$

\textbf{Usage:}
\begin{lstlisting}[language=Python]
length = domain.euclidean_length()  # Returns geometric length
\end{lstlisting}

\paragraph{center\_point()}\leavevmode
\begin{lstlisting}[language=Python, caption=Center Point Calculation]
def center_point(self) -> Tuple[float, float]
\end{lstlisting}

\textbf{Returns:} \texttt{Tuple[float, float]} - Midpoint coordinates $(x_c, y_c)$

\textbf{Formula:} $x_c = \frac{x_1 + x_2}{2}$, $y_c = \frac{y_1 + y_2}{2}$

\textbf{Usage:}
\begin{lstlisting}[language=Python]
center = domain.center_point()  # Returns (x_center, y_center)
\end{lstlisting}

\paragraph{direction\_vector()}\leavevmode
\begin{lstlisting}[language=Python, caption=Direction Vector Calculation]
def direction_vector(self) -> Tuple[float, float]
\end{lstlisting}

\textbf{Returns:} \texttt{Tuple[float, float]} - Unit direction vector from start to end

\textbf{Formula:} $\vec{u} = \frac{(x_2-x_1, y_2-y_1)}{||(x_2-x_1, y_2-y_1)||}$

\textbf{Usage:}
\begin{lstlisting}[language=Python]
direction = domain.direction_vector()  # Returns (u_x, u_y)
\end{lstlisting}

\subsubsection{Boundary Type Constants}
The module defines special constants that can be leveraged for applying boundary conditions:
\begin{itemize}
	\item \texttt{EXTERIOR\_BOUNDARY = -1}: Standard exterior boundary
	\item \texttt{PERIODIC\_BOUNDARY = -2}: Periodic boundary condition
	\item \texttt{SYMMETRY\_BOUNDARY = -3}: Symmetry boundary condition
\end{itemize}

\begin{lstlisting}[language=Python, caption=Build Grid Geometry Function]
def build_grid_geometry(N: int = 4) -> DomainGeometry
\end{lstlisting}

Creates a default organ-on-chip grid geometry with vertical segments and horizontal connectors, including explicit connections.

\textbf{Parameters:}
\begin{itemize}
    \item \texttt{N}: Number of horizontal segments in each section (default: 4)
\end{itemize}

\textbf{Returns:} \texttt{DomainGeometry} - Grid geometry with 4 vertical segments and 4N horizontal connectors

\textbf{Usage:}
\begin{lstlisting}[language=Python]
from bionetflux.geometry.domain_geometry import build_grid_geometry

grid_geom = build_grid_geometry(N=6)
print(f"Grid has {grid_geom.num_domains()} domains")
print(f"Grid has {grid_geom.num_connections()} connections")
\end{lstlisting}

def build_arc_sequence_geometry(N: int = 2, start: float = 0.0, length: float = 1.0) -> DomainGeometry

\subsection{Complete Usage Example}
\label{subsec:complete_example}

\begin{lstlisting}[language=Python, caption=Complete Geometry Usage Example]
from bionetflux.geometry.domain_geometry import (
    DomainGeometry, EXTERIOR_BOUNDARY, PERIODIC_BOUNDARY
)

# Create geometry for Y-junction network
geometry = DomainGeometry(name="y_junction_network")

# Add main vessel (horizontal segment)
main_id = geometry.add_domain(
    extrema_start=(0.0, 0.0),
    extrema_end=(2.0, 0.0),
    name="main_vessel",
    display_color="red",
    vessel_type="parent",
    diameter=1.0
)

# Add upper branch
upper_id = geometry.add_domain(
    extrema_start=(2.0, 0.0),
    extrema_end=(3.0, 1.0),
    name="upper_branch",
    display_color="green",
    vessel_type="daughter",
    diameter=0.7
)

# Add lower branch  
lower_id = geometry.add_domain(
    extrema_start=(2.0, 0.0),
    extrema_end=(3.0, -1.0),
    name="lower_branch",
    display_color="blue",
    vessel_type="daughter",
    diameter=0.7
)

# Set global properties
geometry.set_global_metadata(
    fluid_type="blood",
    viscosity=0.004,  # Pa·s
    density=1060,     # kg/m³
    problem_type="organ_on_chip"
)

# Add boundary conditions
geometry.add_exterior_boundary(
    domain_id=main_id, parameter=0.0,
    boundary_condition="dirichlet", pressure=100.0
)
geometry.add_exterior_boundary(
    domain_id=upper_id, parameter=geometry[upper_id].domain_length,
    boundary_condition="neumann", flux=0.0
)
geometry.add_exterior_boundary(
    domain_id=lower_id, parameter=geometry[lower_id].domain_length,
    boundary_condition="neumann", flux=0.0
)

# Add interior connections at junction point
geometry.add_connection(
    domain1_id=main_id, domain2_id=upper_id,
    parameter1=geometry[main_id].domain_length, parameter2=0.0,
    connection_type="bifurcation", continuity="pressure"
)
geometry.add_connection(
    domain1_id=main_id, domain2_id=lower_id,
    parameter1=geometry[main_id].domain_length, parameter2=0.0,
    connection_type="bifurcation", continuity="pressure"
)

# Analyze geometry
print(geometry.summary())
print(f"\nTotal network length: {geometry.total_length():.3f}")
print(f"Number of connections: {geometry.num_connections()}")

# Validate geometry
if geometry.validate_geometry(verbose=True):
    print("✓ Geometry validation passed")
else:
    print("✗ Geometry validation failed")

# Analyze connectivity
connectivity = geometry.get_connectivity_info()
print(f"Connected components: {connectivity['num_components']}")
print(f"Is fully connected: {connectivity['is_connected']}")

# Access individual domains
for domain in geometry:
    center = domain.center_point()
    direction = domain.direction_vector()
    print(f"\nDomain {domain.name}:")
    print(f"  Center: ({center[0]:.2f}, {center[1]:.2f})")
    print(f"  Direction: ({direction[0]:.2f}, {direction[1]:.2f})")
    print(f"  Color: {domain.display_color}")
    
    # Access metadata
    if "diameter" in domain.metadata:
        print(f"  Diameter: {domain.metadata['diameter']}")

# Query connections by type
boundary_conns = geometry.get_boundary_connections()
interior_conns = geometry.get_interior_connections()
print(f"\nBoundary connections: {len(boundary_conns)}")
print(f"Interior connections: {len(interior_conns)}")

for conn in boundary_conns:
    boundary_type = conn.get_boundary_type()
    print(f"  Domain {conn.domain1_id} $\to$ {boundary_type} boundary")

for conn in interior_conns:
    print(f"  Domain {conn.domain1_id} $\leftrightarrow$ Domain {conn.domain2_id}")

# Find specific domain
main_domain_id = geometry.find_domain_by_name("main_vessel")
if main_domain_id is not None:
    main_domain = geometry[main_domain_id]
    print(f"\nMain vessel length: {main_domain.euclidean_length():.3f}")

# Run comprehensive self-test
print(f"\nSelf-test result: {'PASS' if geometry.run_self_test(verbose=False) else 'FAIL'}")
\end{lstlisting}

\subsection{Integration with BioNetFlux}
\label{subsec:bionetflux_integration}

The \texttt{DomainGeometry} class is designed for seamless integration with BioNetFlux components:

\begin{lstlisting}[language=Python, caption=BioNetFlux Integration Example]
from bionetflux.core.problem import Problem
from bionetflux.core.discretization import Discretization, GlobalDiscretization

# Create BioNetFlux problems from geometry
def geometry_to_problems(geometry, neq=4, parameters=None):
    """Convert geometry domains to BioNetFlux Problem instances."""
    problems = []
    
    for domain in geometry:
        problem = Problem(
            neq=neq,
            domain_start=domain.domain_start,
            domain_length=domain.domain_length,
            parameters=parameters or np.ones(9),  # OrganOnChip parameters
            problem_type="organ_on_chip",
            name=domain.name
        )
        problems.append(problem)
    
    return problems

# Create discretizations from geometry
def geometry_to_discretizations(geometry, n_elements=10):
    """Convert geometry domains to BioNetFlux Discretization instances."""
    discretizations = []
    
    for domain in geometry:
        disc = Discretization(
            n_elements=n_elements,
            domain_start=domain.domain_start,
            domain_length=domain.domain_length,
            stab_constant=1.0
        )
        discretizations.append(disc)
    
    return GlobalDiscretization(discretizations)

# Extract connection information for constraint generation
def extract_constraints_from_geometry(geometry):
    """Extract constraint information from geometry connections."""
    constraints = []
    
    # Boundary constraints
    for conn in geometry.get_boundary_connections():
        domain = geometry.get_domain(conn.domain1_id)
        
        if conn.is_exterior_boundary():
            constraint = {
                'type': 'boundary',
                'domain_id': conn.domain1_id,
                'parameter': conn.parameter1,
                'condition': conn.metadata.get('boundary_condition', 'neumann'),
                'value': conn.metadata.get('value', 0.0)
            }
            constraints.append(constraint)
    
    # Interior connection constraints
    for conn in geometry.get_interior_connections():
        constraint = {
            'type': 'interior',
            'domain1_id': conn.domain1_id,
            'domain2_id': conn.domain2_id,
            'parameter1': conn.parameter1,
            'parameter2': conn.parameter2,
            'continuity': conn.metadata.get('continuity', 'trace')
        }
        constraints.append(constraint)
    
    return constraints

# Usage with factory functions
from bionetflux.geometry.domain_geometry import build_grid_geometry, build_arc_sequence_geometry

# Create standard geometries
grid_geom = build_grid_geometry(N=4)
arc_geom = build_arc_sequence_geometry(N=3, start=0.0, length=1.0)

# Convert to BioNetFlux components
grid_problems = geometry_to_problems(grid_geom)
arc_discretizations = geometry_to_discretizations(arc_geom)

# Extract constraints for solver setup
grid_constraints = extract_constraints_from_geometry(grid_geom)
print(f"Grid geometry has {len(grid_constraints)} constraints")

# Validate before processing
if grid_geom.validate_geometry():
    print("Grid geometry is valid and ready for simulation")
    connectivity = grid_geom.get_connectivity_info()
    if connectivity['is_connected']:
        print("All domains are properly connected")
\end{lstlisting}

This enhanced API provides comprehensive geometry management with connection tracking, validation, and direct integration paths to the BioNetFlux solver framework. The connection system enables precise boundary condition specification and constraint generation for complex multi-domain problems.
